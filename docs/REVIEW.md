## 要検証(実機で確認してください) / Please verify on the device

1. **Android 17のDND**: Android 15以降、アプリはグローバルなDNDを直接変更できず、アプリ専用の暗黙ルールを操作します。システムは全ルールを合成し、最も厳しいものが優先されます。(未確認: Android 17での挙動)
   - 解除 = 「このアプリのルールをオフ」。オン前にユーザー自身がDNDを入れていた場合、それは残ります(解除時に注意を表示)。
   - 「DND: オフ」のプロファイルは、ユーザーや他のモードが入れたDNDを消せません(注意を表示)。
2. **許可した着信がバイブのみで届くか**: 着信音=バイブ + DND優先のみ(着信を許可)で、音が鳴らず振動だけになるか。
3. **アラーム**: 「アラームを通す」をオフにして、お使いの時計アプリで本当に止まるか(アプリによっては音量を無視して鳴ることがあります)。
4. **省電力機能**: メーカー独自の省電力でBTの受信機や自動解除が止まる場合があります。強制停止中はBTイベントも自動解除も働きません。
5. **正確なアラーム**: 許可がないと自動解除が数分遅れることがあります(遅れる=静かなまま、の安全側)。

## 「消音中に音が鳴る」経路の点検 / Ways the phone could get LOUD (all checked)

| 経路 | 対策 |
|---|---|
| 変更の途中で元の状態に戻れなくなる | 変更**前**に元の状態をディスクへ保存(commit) |
| 反映されたと思い込む | すべて読み戻して確認。少しでも大きな音なら再試行→失敗なら元の静かな状態に戻して理由を表示 |
| 切り替え(プロファイルA→B)の失敗 | 失敗時は「元の大きな音」ではなく**直前の静かなプロファイル**へ戻す |
| 解除に失敗 | 「オン」のまま残す(静かな側。ただしDNDだけ先に戻って着信音がバイブのまま、の可能性はある)。自動解除での失敗は60秒後に再試行(最大2回で打ち切り、ループしない)。手動解除の失敗は自動再試行しない。2回失敗したら状態を閉じて理由を通知 |
| 編集中の(オン中の)プロファイルの適用に失敗 | 巻き戻し先は**編集前の内容**(第3回で修正。以前は編集後の内容を再適用してしまい、元の大きな音の状態まで戻る可能性があった) |
| ウィジェットのダブルタップで「オン→すぐオフ」 | オン直後2秒以内のウィジェットタップは無視(第3回で追加) |
| BT切断時のメディア許可の取り消しに失敗 | 「同期済み」として保存しない。通知で知らせ、60秒後に再確認(第3回で追加) |
| 有効化直後にBT機器が一覧に残っている | 10秒後にもう一度確認(第3回で追加) |
| 他アプリ/ユーザーが「優先のみ」の許可項目を広げた | 再確認時に書き戻す(第3回で追加。Android 17でのポリシー読み戻しの挙動は未確認) |
| 自分の通知が鳴る | 全チャンネルを音なし・バイブなし・低重要度に固定 |
| BT切断後にメディア許可が残る | 切断された機器を即時に除外して判定。3秒後・7秒後にも再確認。ポリシー更新失敗は次のイベントで再試行 |
| **BLUETOOTH_CONNECT未許可でBT切断が届かない** | 許可がなければ常に「未接続」扱い(メディアを許可しない)。※第2回レビューで追加 |
| 音量キー等で外部から変更された | 上書きしない。「オフ」として扱い、状態を閉じ、このアプリのDNDルールもオフにする(隠れたDNDを残さない)。**検出はウィジェットのタップ・アプリを開く・自動解除・再起動・BT/再確認アラームの時点で、変更の瞬間ではありません**(通知やウィジェットは次の確認まで「オン」表示のことがあります) |
| 通知をスワイプで消された | 削除インテントで再投稿(状態がオンの間のみ) |
| ウィジェットの古い表示のままタップ | タップ時に実際の状態を再確認してから動作 |
| 解除時の音量復元が着信音を鳴らす | 着信音・通知音の音量は、復元する着信音モードが「音あり」の時だけ触る。着信音/DNDの復元**後**に音量を戻す |

## セキュリティ点検 / Security checklist

- INTERNET権限なし。`allowBackup=false`。データは端末内(SharedPreferences、アプリ専用フォルダ)のみ
- exported=true は、システム/ランチャーが呼ぶ必要があるものだけ(BootReceiver / BtReceiver / ウィジェット2種 / WidgetConfigActivity / MainActivity)
  - 受信機は保護ブロードキャスト(アプリから送れない)のみを受け、コード内でも action を再確認
  - WidgetConfigActivity はウィジェットIDが自アプリのものか検証
  - ウィジェットの「削除」を偽装されても、実在するIDは無視(※第2回で追加)
- ExpireReceiver / ActionReceiver / TapActivity / ProfileEditActivity は exported=false
- PendingIntent はすべて FLAG_IMMUTABLE。ウィジェットのタップは固有のデータURIで区別
- 画像は自アプリのフォルダへ小さなPNGとしてコピー(ファイル名は `File(name).name` でパス移動を防止、巨大画像は拒否)
- デバッグ署名鍵は**公開**(`app/debug.keystore`)。配布・リリースには使わないでください

## インポートの安全性 / Import safety

読み込むJSONは信頼しない入力として扱います: ファイルは8MBまで、プロファイルは100件まで、すべての値を範囲内に丸め、画像はデコードして小さなPNGに作り直し(ファイル内の名前は使わない)、すべて検証してから置き換えます。プロファイルがオン中は読み込みを拒否します(バックアップが勝手に何かをオンにすることはありません)。

## 既知の制約 / Known limits

- 強制停止、メーカー独自の省電力による受信機の停止(上記)
- BT判定は「オーディオ出力機器」から行う(スマートウォッチやキーボードの接続では動きません)。ヘッドセットのみ判定はBluetoothクラスに依存し、機器によっては分類されないことがあります
